## 2. 主流前端設計研究

| 參考 | 觀察 | 本站採用 |
|------|------|----------|
| **Linear** | 低飽和中性色、極少裝飾、資訊密度高但層級清楚 | 中性色面板 + 單一強調色；不用漸層背景與玻璃擬態 |
| **Vercel（Geist）** | 系統字體般的乾淨字型、表格數字等寬、深淺色同等重要 | `font-variant-numeric: tabular-nums` 用在所有數字；深色模式不是事後補色 |
| **Stripe** | 精準的間距系統、說明文字短而明確 | 4 px 間距尺度；每個區塊一句「這張圖怎麼讀」 |
| **The Athletic** | 編輯感：先講結論再給資料 | Hero 標題直接是結論句，不是口號 |
| **Apple Sports** | 比分是主角：大數字、隊名、其他資訊退後 | 比分盒置中、勝方加粗、敗方降灰；PK／延長以小字附註 |
| **Observable** | 圖表誠實、直接標註、少圖例 | 機率值直接寫在條上或旁邊；校準圖用「空心＝說的、實心＝實際」點圖 |
| **Radix / shadcn/ui** | 無障礙行為（dialog、焦點管理）與 token 命名（background、card、muted、ring…） | 沿用 shadcn token 命名；單場詳情用原生 `<dialog>` 取得焦點陷阱、Esc、背景 inert |
| **Tailwind** | 設計 token 先行、行動優先的斷點 | 行動優先 CSS，斷點 600／720／900／1200；token 命名可直接搬進 Tailwind v4 `@theme` |
| **Design tokens（W3C DTCG 概念）** | 顏色、字級、間距、圓角以語意命名 | 所有顏色只定義在 `:root` 與深色覆寫中，元件只引用語意 token |

### 2.1 本站設計語言（已落實於 `src/styles.css`）

- **色彩**：中性灰階 + 單一強調藍（淺 `#1d4ed8`／深 `#7aa2ff`）。機率三色採色盲友善的 **藍（主）／灰（和）／橘（客）**。判定：綠 ✓ 猜中、紅 ✗ 猜錯、琥珀 ★ 比分全中——**一定搭配圖示與文字，不只靠顏色**。
- **字體**：系統字體堆疊（PingFang TC／Noto Sans TC／Microsoft JhengHei），不載入網路字型，避免版面跳動與額外流量。
- **層級**：每頁一個 H1；區塊 H2 + 一句說明；數字用大字、標籤用小字灰色。
- **元件**：卡片（1 px 邊框、極淡陰影）、分段控制、機率條、判定膠囊、量表條、點圖、走勢線，全部手寫 SVG／CSS，**沒有新增任何相依套件**。
- **動態**：只有抽屜滑入與骨架閃爍；`prefers-reduced-motion` 時關閉。
- **深淺色**：跟隨系統，可在頂欄切換（系統／淺／深），選擇存在 localStorage，並在首次繪製前套用。

### 2.2 為什麼沒有直接裝 Tailwind／shadcn

專案只有一個頁面、相依只有 React 與 Vite，且 bot 會定期在同一個 repo 建置部署。加入 Tailwind／Radix 會增加建置相依與升級風險，收益有限。改採「shadcn 的 token 命名 + 原生 `<dialog>` + 純 CSS」：行為面得到同等的無障礙保證，未來若要遷移，token 可一對一搬過去。

## 4. 裝置評估

| 資料 | 手機 | 桌機 | 平板 | 來源 |
|------|------|------|------|------|
| 台灣整體網路流量（2026-09） | 58.1% | 38.6% | 3.4% | StatCounter ✔ |
| 全球整體網路流量（2026-09） | 59.0% | 39.3% | 1.8% | StatCounter ✔ |
| 本站實際流量 | — | — | — | 站點未安裝分析工具，**無法驗證** |

推估：本站流量主要來自社群與通訊軟體分享的連結，這類流量通常比整體平均更偏手機（推論，◇ 未驗證）。合理估計 **手機約 65–75%、桌機約 25–35%**。

**結論：手機為主力裝置（以 390 px 寬設計與驗收），桌機為一等的次要裝置。** 具體做法：

- 版面從單欄手機版開始寫，桌面再展開為雙欄、六欄賽事列與完整對戰樹。
- 所有可點元素 ≥ 44×44 px；表單輸入字級 16 px（避免 iOS 自動放大）。
- 頂欄在手機上捲動後只留分頁列（品牌列自動收起），桌機則一列整合。
- 單場詳情：手機是底部抽屜，桌機是右側面板（列表仍可見，方便逐場翻閱）。
- 情報檔（0.7 MB）延後載入，照顧行動網路。

## 5. 視覺標準與實測

做完第一版後我覺得畫面沒有焦點、沒有對齊、字偏小，所以寫了一支 audit 腳本（Playwright）：統計可見文字的字級分佈、首屏最大的幾段文字、寬區塊的左緣 x 值，同樣量測幾個標竿網站與本站。數字都是實際跑出來的 ✔。

### 5.1 標竿實測

| 網站 | 寬度 | < 14px 佔比 | 主要字級 | 首屏焦點（字級／字重） | 焦點倍率 |
|------|------|-------------|----------|------------------------|----------|
| Linear | 1440 | 45% | 15px 25%、13px 23%、12px 19% | 64／510 標題，下一層 20px | **3.2×** |
| Linear | 390 | 47% | 15px 28%、12px 27% | 38px 標題 | — |
| Stripe | 1440 | 12% | **16px 38%**、22px 16%、26px 15% | 48／300 標題 | — |
| Stripe | 390 | 14% | **16px 44%**、20px 24% | 34px 標題 | — |
| FotMob | 1440 | 22% | 14px 68% | 19px（導覽列），沒有明確焦點 | — |

借鏡：焦點比例學 Linear（一個大數字，第二層只有它的一半以下）；內文字級學 Stripe（16px 為主、小於 14px 的字壓在 15% 以內）。FotMob 是資料密集的反例：14px 佔 68%、首屏沒有焦點。

### 5.2 規則

- **字級階梯固定**：12 / 14 / 16 / 18 / 22 / 28 / 36 / 48 / 64 / 96，CSS 只能用 `--fs-*` token。內文、列表、表格主體 16px；次要說明 14px；12px 只留給圖表軸標、PK 註記與時間戳。
- **單一焦點**：首屏只有「61.5% 勝負命中率」用強調色與最大字級；結論句、冠軍、KPI 都降一級且不用狀態色。紙上本金原本是綠色大字，會搶焦點，改成中性色。
- **格線與左緣**：內容寬 1400px，桌面 gutter 20px；首屏三等欄、欄距 24px，區塊的左緣只有少數幾條。
- **間距只用 8pt 階梯**：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64。
- **Squint 檢查**：首屏模糊後只應剩一個深色塊（焦點數字）。

## 6. 版面參考

總覽頁的版面比例參考了一個公開的足球賽事資料 hub 頁面：1400px 容器、首屏三等欄（欄距 24px）、白卡加 48px 灰色標頭帶、6px 圓角與 3px 硬邊陰影、斑馬紋等寬字體表格、一條深色導覽列加一條深色全幅帶。只參考結構與比例，沒有使用任何 logo、照片、插圖或文案，配色也是自己的（深藍／藍／青）。

| 項目 | 本站 |
|---|---|
| 容器與間距 | `--container: 1400px`、`--gutter: 20 / 16`、`--gap: 24`（手機 12） |
| 卡片 | `.ocard`：白底、圓角 6、`0 3px 0` 硬邊陰影、內距 24（手機 16） |
| 卡片標頭帶 | `.ocard-head`：48px、`--band` 灰、22/700 uppercase |
| 導覽列與狀態帶 | `.navbar`（深藍）、`.strip`（資料驗證、完賽數、快照時間） |
| 表格 | 等寬字體、列高 36、斑馬紋、Soren 列用 `--highlight` |
| 全幅深色帶 | `.band` 四張 `.band-card`：最有把握命中／猜錯、各階段、風險標籤 |
| 字體 | 標題與數字用 Big Shoulders Text、表格用 IBM Plex Mono（皆 Google Fonts，OFL）；內文維持系統中文字體，因為沒有 CJK 版本 |

字級仍以第 5 節的 16px 基準為準，不照搬參考頁的 13px 內文：標頭帶 22、h1 28、焦點數字 96（手機 48）、表格 14 mono。
